# Bitwarden.Server.Sdk.Crypto

C# facade over the Rust SDK, through [UniFFI](https://github.com/mozilla/uniffi-rs) bindings
generated by [uniffi-bindgen-cs](https://github.com/NordSecurity/uniffi-bindgen-cs).

```
sdk-internal                              this package
crates/bitwarden-uniffi-server ──cdylib──▶ native/runtimes/<rid>/native/   (fetched, gitignored)
                                              │ uniffi-bindgen-cs --library
                                              ▼
                                           src/Generated/*.cs              (committed, internal)
                                              │
                                           NativeServerSdk ──▶ ICryptoParsingClient, IServerSdkInfo
```

Generated types stay `internal`; only the domain interfaces and their result records and
algorithm enums are public.

## Local development

Requires a Rust toolchain and an sdk-internal checkout.

```bash
scripts/fetch-native.sh --from-source ../../../sdk-internal   # build for the host RID
scripts/generate-bindings.sh                                  # only when the Rust API changed
dotnet test --project tests/Bitwarden.Server.Sdk.Crypto.Tests
```

## Bumping the Rust SDK

1. Run the `build-uniffi-server.yml` workflow in sdk-internal and set `SDK_INTERNAL_RUN_ID` in
   `sdk-internal.env` to its run id.
2. `scripts/fetch-native.sh --from-pinned`, then `scripts/generate-bindings.sh`.
3. Commit `sdk-internal.env` and `src/Generated/`. CI fails if the bindings drift from the pinned
   binaries (`generate-bindings.sh --check`).

When sdk-internal bumps `uniffi`, bump `UNIFFI_BINDGEN_CS_TAG` to the release targeting it.

## Native library resolution

- NuGet consumers: `runtimes/<rid>/native/` via `deps.json`.
- ProjectReference consumers: the same files are copied to the output, and `NativeLibraryResolver`
  probes `runtimes/<rid>/native/` there, since no `deps.json` entry exists.
